# Изменения

Сверху — новые. Номер версии совпадает с тегом релиза и тегом образа. Раздел версии попадает на
страницу релиза в «Что нового».

## 2.0.0 — 2026-10-26

**Сервис переведён на модули EAMS** — модульный монолит, где каждый общий модуль живёт в своём
репозитории `danrey-bilo/module-*`. Учётные записи, сессии, настройки, почта, крипта и конвейер
запросов теперь — модули EAMS; своё у проекта — хост, модуль Key Manager Plus и панель. Обновление
с 1.x — README, «Обновление до 2.0»: **сначала копия базы**, затем `migrate`.

### Модули

- Подключены подмодулями `modules/<имя>`, только нужные проекту, каждый **закреплён коммитом метки**
  и сам не обновляется: core `v0.9.0`, crypto `v0.5.0`, hosting `v0.6.0`, identity `v0.10.0`,
  tokens `v0.8.1`, settings `v0.8.1`, mail `v0.9.0`. Переход на другую версию — только явным
  коммитом подмодуля (docs/REFERENCE.md, «Модули EAMS подмодулями»).
- Модули доработаны в EAMS так, чтобы прежнее поведение EAMS не изменилось — всё новое включается
  опциями (решение EAMS 0120):
  - **core + mail:** вложения письма, номер письма, состояние писем (ждёт / ушло / не ушло) и отмена
    неотправленных; виды писем вне предела частоты; рамка письма (приветствие и подпись с именем
    продукта, `Frame`) и привязка пароля SMTP к серверу (`BindSmtpPassword`);
  - **hosting:** окно свежего кода второго фактора — из настройки, в отказе `details.window_minutes`;
  - **identity:** настройка `auth.step_up_minutes`, поле `step_up_until`, проверка ссылки активации
    POST-ом, восстановление доступа из консоли одной транзакцией и опции входа: код письмом не
    заменяет приложение, сессия настройки аутентификатора для всех, кука обновления не уходит в тело,
    предел кодов на попытку входа, «последний администратор» — только способный войти, ограничитель
    параллельного хеширования паролей.
- Удалены собственные `EmailSslSender.Shared`, `EmailSslSender.Modules.{Identity,Tokens,Settings,Mail}`
  и их тесты: их место заняли модули. Модуль Key Manager переведён на контракты ядра модулей
  (`Modules.Core`, `Modules.Crypto`) и несёт свой набор миграций.
- Что проект задаёт модулям опциями (имя куки, издатель TOTP, обязательный аутентификатор, имя
  сервиса в письмах, выключенные подвозможности — ключи интеграции, доверенные браузеры, расширение,
  справочник людей) — таблица в docs/REFERENCE.md, «Что проект задаёт модулям».

### Перенос данных (`migrate`)

- Прежние миграции хоста дотягиваются до моста **`ModulesBridge`**: недостающие колонки, ограничения
  и индексы схемы модулей, таблица `user_preferences`; каждая учётная запись становится
  суперпользователем (ролей нет, администраторы равны). Базовые миграции модулей отмечаются
  применёнными, остальные выполняются; у каждого модуля своя таблица истории `__ef_history_<модуль>`.
- **Секреты перекладываются** в конверт модулей тем же мастер-ключом: секреты TOTP, пароль SMTP,
  ключ API Key Manager Plus. Идемпотентно; повторный `migrate` ничего не меняет.
- Неотправленные письма (тела запечатаны прежним конвертом) отмечаются неотправленными.
- Набор миграций проекта задаёт окно свежего кода **10 минут** (умолчание модуля — 5) и на новой, и
  на обновлённой установке.
- Проверено на копии живой базы: все секреты переложены, схема совпадает со схемой новой установки;
  тест `ModulesBridgeTests` держит это сравнением каталога.

### Что изменилось для администраторов

- После обновления **все входят заново**; ссылки приглашений и сброса пароля, выданные до обновления,
  не действуют — выдайте снова.
- **Свежий код спрашивают чаще:** правка любой настройки (не только защиты), правка учётной записи
  (и имени), проверочное письмо, смена своего пароля. Панель спрашивает код сама.
- Новые пользователи из панели заводятся суперпользователями — как и прежде, каждый администратор.
- `GET /api/activation?token=` по-прежнему закрыт (`405`): ссылка приглашения передаётся телом
  запроса; модуль держит этот путь ради клиентов EAMS, хост его закрывает.
- Письмо с сертификатом — прежнего вида: список файлов в архиве — по строке на файл. Модуль почты
  вырезает переводы строк из подставляемых значений, поэтому вид письма выбирается по числу файлов
  (`certificate_delivery_1` … `_9`).
- Журнал (`audit` в логе): значения изменений — у настроек и Key Manager Plus, у прочих событий —
  имена полей; отказы в праве — строкой `authz.denied`.
- В образе нет ничего нового снаружи: тот же `docker compose`, те же переменные и секреты.

### Сборка

- Клонировать с подмодулями: `git clone --recurse-submodules`. Репозитории модулей закрытые.
- Сборка образа в GitHub Actions забирает подмодули секретом **`MODULES_TOKEN`** (fine-grained токен,
  `Contents: Read-only` на `email_ssl_sender` и семь `module-*`).
- В `Directory.Packages.props` — пакеты, нужные модулям сверх наших: BouncyCastle.Cryptography,
  Npgsql, Serilog, StackExchange.Redis (последний — только для сборки модуля хостинга, Redis сервис
  не использует). Модули собираются по правилам проекта.

## 1.4.0 — 2026-10-26

- **Письмо с сертификатом — одним архивом ZIP** `<имя>.zip`: Outlook блокирует вложения `.crt`,
  `.cer` и `.der`. Пароль ключа — файлом `passphrase.txt` в том же архиве.
- **Письма человеческие:** приветствие, суть (сертификат, форматы, срок действия, что в архиве) и
  подпись «Спасибо, EAMS ssl sender». Та же рамка — у приглашений, сброса пароля, кодов входа и
  проверки почты.
- **Сервис называется «EAMS ssl sender»:** панель, письма, отправитель по умолчанию, запись в
  приложении-аутентификаторе. Миграция `RenameSenderName` заменяет сохранённое прежнее имя
  отправителя «Email SSL Sender»; имя, заданное вручную, не трогается.
- **Скачивание с сайта:** файл сохраняется с нужным расширением — телефон больше не дописывает своё
  (`.crt.cer`, `.key.pem`).
- [docs/KEYMANAGER-API.md](docs/KEYMANAGER-API.md) — какие методы REST API Key Manager Plus вызывает
  сервис и что каждый даёт.

## 1.3.1 — 2026-10-20

- Удалено унаследованное от EAMS, что ни на что не влияло:
  - личный выбор способа второго фактора (`PUT /api/me/two-factor`, поле `chosen_method`) и
    настройка `auth.second_factor`. Способ определяется так же, как и раньше: подтверждён
    аутентификатор — код из приложения, иначе код письмом при настроенной почте;
  - поле `scope` у настроек (`GET /api/settings/system`) и код ошибки `SETTING_LEVEL_FORBIDDEN`;
  - неиспользуемые очередь «после фиксации» транзакций и проверка подписанных значений.
- Миграция `RemoveSecondFactorMethod` удаляет колонку `users.second_factor_method`: после
  обновления выполните `migrate` (в Portainer — само).

## 1.3.0 — 2026-10-20

- **Рассылка на телефоне:** «⋯» у подписки открывает лист снизу со всеми действиями — отправить,
  изменить, включить или отключить, удалить. На компьютере у подписки появилась кнопка
  «Отключить» / «Включить».
- Меню действий больше не обрезается краем таблицы — ни у подписок, ни у пользователей.
- Сервис пишет свою версию в журнал при старте (`sender_starting`), образ собирается с номером
  версии из тега.
- Зависимости: EF Core и ASP.NET Core 10.0.13, MailKit 4.18.1, Testcontainers 4.16, сборка панели
  на Node 24, действия GitHub Actions — текущие версии.
- Порядок в коде: стили панели разложены по разделам, убраны неиспользуемые части и устаревшие
  комментарии, лишние `using` теперь останавливают сборку.

## 1.2.0 — 2026-10-20

- «Сертификаты» показывают только то, что пришло в последнем опросе Key Manager Plus; пропавшие
  забываются через 30 дней.
- «Безопасность» — настройки по категориям и одна кнопка «Сохранить».
- Архив для Portainer: `docker-compose.yml`, `.env.example`, образ и инструкция. Служба `migrate`
  выполняется при каждом развёртывании; первый администратор и сброс доступа задаются
  переменными стека.

## 1.1.0 — 2026-10-20

- Вкладки «Сертификаты» (скачать файл, показать закрытый ключ), «Настройки» (почта, Key Manager)
  и «Безопасность».
- Скачивание сертификатов и ключей, изменения настроек, людей и подписок подтверждаются кодом из
  приложения; код действует 10 минут (`auth.step_up_minutes`).

  транзакцией.
- Неактивированное приглашение больше не позволяет последнему администратору удалить или
  отключить себя. Панель отправляет только изменённые настройки.
