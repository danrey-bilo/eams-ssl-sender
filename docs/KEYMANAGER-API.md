# Key Manager Plus: какие API использует сервис

Сервис только **читает** ManageEngine Key Manager Plus (KMP): берёт список SSL-сертификатов, файлы
сертификатов и ключей, пароль закрытого ключа. Ничего в KMP не создаёт, не продлевает и не меняет.

Проверено на Key Manager Plus **7.1.1 (build 7110)**. Документация производителя:
<https://www.manageengine.com/key-manager/help/restapi.html>.

Весь протокол KMP живёт в одном месте кода —
[`KeyManagerClient`](../EmailSslSender.Modules.KeyManager/Client/KeyManagerClient.cs).

## Как сервис обращается к KMP

| | |
|---|---|
| Адрес | `keymanager.base_url` из настроек, только `https://`, например `https://kmp.example.com:6565` |
| Путь | `/api/pki/restapi/<метод>` |
| HTTP | `GET` |
| Ключ API | заголовок `AUTHTOKEN: <ключ>` — ключ из KMP: **Settings → General Settings → API Key** |
| Параметры | JSON `{"operation":{"Details":{…}}}` в параметре строки запроса `INPUT_DATA` (закодированный) |
| TLS | обычная проверка цепочки и отзыва; для самоподписанного сертификата KMP — закреплённый отпечаток SHA-256 (`keymanager.server_sha256`) |
| Перенаправления | выключены: по ним ключ API ушёл бы на другой адрес |
| Тайм-ауты | соединение — 15 с, запрос целиком — 30 с |

Пример запроса (ключ — заголовком, не в адресе):

```http
GET /api/pki/restapi/getCertificate?INPUT_DATA=%7B%22operation%22%3A%7B%22Details%22%3A%7B%22common_name%22%3A%22site.example.com%22%2C%22serial_number%22%3A%220a1b2c%22%2C%22fileType%22%3A%22PEM%22%7D%7D%7D HTTP/1.1
Host: kmp.example.com:6565
AUTHTOKEN: 00000000-0000-0000-0000-000000000000
```

## Используемые методы

| Метод KMP | Что даёт сервису | Где в сервисе |
|---|---|---|
| `getAllSSLCertsExpiryDate` | Список всех SSL-сертификатов: Common Name, серийный номер, срок действия | Опрос по расписанию, кнопки «Проверить» и «Опросить» в настройках, «Обновить» на вкладке «Сертификаты» |
| `getCertificate` | Сам файл: сертификат в нужном формате или закрытый ключ | Письма подписок, «Скачать» и «Ключ» на вкладке «Сертификаты» |
| `getCertificatePassphrase` | Пароль закрытого ключа | Письмо подписки с флажком «Пароль ключа в письме», окно «Ключ» |

Других методов KMP сервис не вызывает.

## getAllSSLCertsExpiryDate — список сертификатов

**Зачем.** Это единственный метод KMP, который отдаёт серийный номер сертификата. У KMP нет вебхуков и
истории изменений, поэтому продление сервис замечает так: у того же Common Name в списке появился
**новый серийный номер**. Тогда подписки с «При обновлении» получают новый сертификат.

**Запрос.** Без `INPUT_DATA`.

> ⚠ Документация обещает параметр `customExpiryDateFormat` (с build 7040), но фильтр безопасности
> KMP 7.1.1 отвечает на `INPUT_DATA` у этого метода `400 EXTRA_PARAM_FOUND`. Поэтому параметров нет,
> а дата разбирается из `ExpiryDate`.

**Что берём из ответа** — массив `details`:

| Поле | Что это | Как используем |
|---|---|---|
| `Common Name` | Имя сертификата (`site.example.com`, `*.example.com`) | Имя в подписке, на вкладке «Сертификаты», в письме |
| `serialNumber` | Серийный номер (hex) | Отличает новый выпуск от прежнего; сравнивается без учёта регистра |
| `ExpiryDate` | Срок действия, вида `Oct 2, 2025` | «Действует до» в панели и в письме, отметки «истёк / N дн.» |

Строка без имени или серийного номера пропускается — остальные от неё не зависят.

Результат сохраняется снимком (`keymanager_certificates`). Текущим сертификатом Common Name считается
**замеченный позже всех**, а не самый долгий: перевыпуск сохраняет срок, а новые сертификаты бывают
короче. Сертификаты, пропавшие из KMP, на вкладке не показываются и забываются через 30 дней.

## getCertificate — файл сертификата или ключа

**Зачем.** Выгрузить файлы для письма подписки или для скачивания администратором.

**Параметры** (`INPUT_DATA` → `Details`):

| Параметр | Значение |
|---|---|
| `common_name` | Common Name из списка |
| `serial_number` | Серийный номер из списка — выгружается ровно тот выпуск, что в снимке |
| `fileType` | Один из типов ниже |

| `fileType` | Что внутри | Расширение у нас | В панели |
|---|---|---|---|
| `PEM` | Сертификат, текст PEM | `.pem` | PEM |
| `CRT` | Сертификат | `.crt` | CRT |
| `CER` | Сертификат | `.cer` | CER |
| `DER` | Сертификат, двоичный | `.der` | DER |
| `P7B` | Сертификат с цепочкой (PKCS#7) | `.p7b` | P7B |
| `PKCS` | Сертификат с ключом (PKCS#12) | `.pfx` | PFX |
| `JKS` | Хранилище Java | `.jks` | JKS |
| `KEY` | Закрытый ключ | `.key` | KEY |

**Ответ** — сам файл. Документация формат не описывает («Certificate object»), поэтому сервис
проверяет, что пришло:

- JSON вместо файла — отказ KMP; в причину попадает текст KMP и список ключей ответа, без значений;
- пустой ответ или не похожее на сертификат (не PEM, не DER / PKCS#7 / PKCS#12, не JKS, не ZIP) —
  отказ: страница ошибки прокси с кодом 200 не уйдёт получателю под видом ключа;
- ZIP (KMP упаковал несколько файлов) — принимается как есть и получает имя `….pem.zip`.

Имя файла сервис даёт **сам**: KMP 7.1.1 называет и PEM, и KEY одинаково — Common Name без
расширения. Наше имя — Common Name с расширением типа: `*.example.com` + `PEM` →
`wildcard.example.com.pem`.

**Куда идёт файл:**

- в письме подписки — все выбранные файлы (и `passphrase.txt`, если включён) **одним архивом**
  `wildcard.example.com.zip`: Outlook блокирует вложения `.crt`, `.cer` и `.der`;
- при скачивании из панели — файлом с тем же именем и типом `application/octet-stream`, чтобы телефон
  не дописывал своё расширение (`.crt.cer`, `.key.pem`);
- в окне «Ключ» — тип `KEY`, показанный текстом PEM.

## getCertificatePassphrase — пароль закрытого ключа

**Зачем.** Ключ в KMP может быть защищён паролем; без пароля получатель его не откроет.

**Параметры:** `common_name`, `serial_number`.

**Что берём из ответа:** `details.Passphrase` (или `details[0].Passphrase` — `details` бывает и
объектом, и массивом). Пусто — пароля нет.

Пароль запрашивается только для подписок с флажком «Пароль ключа в письме» и в окне «Ключ». В письме
он лежит файлом `passphrase.txt` внутри архива, а не в тексте письма: текст письма хранится в очереди
до уборки, а вложение стирается сразу после отправки.

## Ответы и отказы

Конверт ответа у KMP непостоянен, и разбор терпим к этому нарочно:

| Что бывает | Как понимает сервис |
|---|---|
| `result.status` у одних методов, плоский `Status` у других | Успех — только явное `success` в любом регистре |
| `Success`, `SUCCESS` | То же |
| `details` — то массив, то объект | Читается любой вид |
| Неверный ключ API: **HTTP 200** и `{"name":"AuthenticationFailure", … "Login Failed!"}` | «Key Manager Plus не принял ключ API» |
| `400 EXTRA_PARAM_FOUND` / `INVALID_METHOD` | Фильтр безопасности KMP: неизвестный параметр или метод |
| `401` / `403` | Ключ API не принят |
| `3xx` | Отказ: по перенаправлению ключ API не отправляется — проверьте адрес |
| Сеть, имя, TLS | Причина словами: имя не разрешается, соединение, TLS (цепочка, имя, отзыв, отпечаток) |

Причина отказа видна администратору: в состоянии Key Manager на странице настроек, в ошибке подписки,
в ответе API (`409 KEYMANAGER_UNAVAILABLE`, `details.reason`). Тело чужих страниц (HTML прокси,
Tomcat) в причину не попадает.

## Когда и сколько запросов

- **Опрос** — раз в `keymanager.poll_minutes` (по умолчанию 15 минут): один
  `getAllSSLCertsExpiryDate`.
- **Файлы** — только когда подписке пора отправлять (новый серийный номер или подошёл интервал), либо
  по кнопке «Отправить сейчас». В одном проходе опроса каждый файл и пароль выгружаются **один раз**,
  даже если сертификат нужен нескольким подпискам.
- **Почта проверяется до выгрузки:** если почта не настроена, закрытые ключи из KMP не выгружаются
  вовсе.
- **Скачивание и «Ключ» в панели** — по одному `getCertificate` (и `getCertificatePassphrase` для
  «Ключа») на нажатие, только для сертификата из последнего опроса и со свежим кодом второго фактора.

## Безопасность

- Ключ API хранится в базе зашифрованным и привязан к адресу KMP и отпечатку: смена адреса требует
  ввести ключ заново, и чужой сервер его не получит.
- Ключ — только в заголовке `AUTHTOKEN`, никогда в адресе: адреса запросов оседают в логах.
- Только `https`, без перенаправлений; отключить проверку сертификата KMP нельзя.
- Рекомендуется отдельная служебная учётная запись KMP для ключа API.
- В журнал сервиса уходят сертификат и тип файла — без содержимого, без ключей и паролей.
